# V0.6.1 — Classic Save / Continue

## Behaviour
- During Classic play a deferred snapshot is attempted roughly once per simulation second; pausing also attempts a save. A snapshot is refused if a drop is uncommitted, a merge is pending/scheduled, or any body is merge-locked. If pause cannot save, return to the menu is blocked with a message; resume and wait for the merge to resolve, or address the storage error. An autosave I/O/validation failure displays a HUD warning and is retried; a pending merge is not treated as a disk error. Restart/new game and game over invalidate the old session. New game asks for confirmation when a usable session exists.
- `user://wild_garden_session.json` has a versioned, SHA-256 checked JSON payload. A temporary file is verified and renamed, with the previous good primary retained as `.bak`. A bad primary falls back to a validated backup. Game-over/new-game tombstones replace both copies so a damaged tombstone does not revive the old session. Unknown newer envelope or session versions are not overwritten. Only local storage is used.
- The validated snapshot contains animal resource ID, per-snapshot identity, position, rotation, linear/angular velocity, sleep state and danger timer; score, best, drop/merge counts, combo and timer, highest tier, current/next, aim/cooldown, tutorial stage and exact RNG state (encoded as a decimal string). On Continue a fresh scene is populated exactly once, only after full validation. No pending pair is serialized. Existing V0.5 best/settings/tutorial files remain in use; this change does not claim a general progression migration.
- Recovery loads the **previous** checkpoint, which can lose recent play. A first-ever saved session may not yet have an active-session backup until the next successful save. Abrupt termination can lose play since the last safe checkpoint; a permanently blocked merge can delay saves. File `flush` and rename are not a demonstrated power-loss durability guarantee, and paired tombstone updates are not a single atomic transaction. Multiple simultaneous writers are unsupported. Physics contact solver internal caches are not serialized, so continuation is not guaranteed bit-identical after subsequent simulation.

## Limits
Linux Godot 4.7.2, CI headless and Xvfb/Mesa software rendering were tested. Real mobile touch, Android/iOS persistence, browser/Web export, Windows filesystem semantics, disk-full/power-loss fault injection, concurrent writers, broad randomized save/load stress and human play have not been verified. The existing final-release art rights and visual acceptance blockers remain; this is a DEV build.
