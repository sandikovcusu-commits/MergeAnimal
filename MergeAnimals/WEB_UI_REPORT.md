# V0.8.1.2 — Web UI / responsive report (partial)

Status: **INCOMPLETE, not release acceptance**. Actual Godot 4.7.2 release WebAssembly exports were served over HTTP in Linux GitHub Actions, using Playwright Chromium and Firefox with software rendering, not native Godot screenshots. Browser/version details, timestamps and raw events are in the evidence ZIP. This is simulated browser QA, not a real Android/iOS or human usability test.

## Results

- [Chromium screens](https://github.com/sandikovcusu-commits/MergeAnimal/actions/runs/45871958154), [Firefox screens](https://github.com/sandikovcusu-commits/MergeAnimal/actions/runs/45871961658): 16 scripted checks each, no reported failures. At 720×1280 Play opened Tutorial; menu buttons opened Collection, Statistics, Achievements, Themes, Challenges and Settings and their Back buttons returned; Pause opened. OCR is an imperfect oracle; screenshots are included. Continue, Challenge gameplay/success/failure, Game Over and individual controls beyond those described are **not established** by these screen tests.
- [Chromium matrix](https://github.com/sandikovcusu-commits/MergeAnimal/actions/runs/45870906297), [Firefox matrix](https://github.com/sandikovcusu-commits/MergeAnimal/actions/runs/45870910681): 360×640, 393×873, 540×1170, 720×1280, 1366×768, 1920×1080. Assertions cover canvas visibility and absence of DOM overflow only; screenshots show menu and gameplay at each size. These runs predate the touch-input fixes, but use the same UI layout. Passing the assertions is **not** proof of no Godot-control clipping, overlap, deformed sprites or usable touch targets. Manual review of Chromium 393×873 and 1366×768 menu and 720×1280 Settings, Collection, Achievements, Themes and Challenges screenshots showed portrait letterboxing and no obvious overlap in the visible portions; scroll content was not fully reviewed.
- The themes screen displayed Forest selected and the other two locked; applying Sunset/Snow and testing their rendering were **not performed**. Screenshots above are English only. Azerbaijani, Turkish and Russian glyphs, long translations and the language selector require real Web verification.
- Orientation/fullscreen exit, tab switch and focus-loss behavior, comprehensive resize and real-device safe areas are **not verified**. The held-touch resize case is covered separately in `MOBILE_TOUCH_REPORT.md`.

Earlier screen runs failed on an OCR false negative for the menu and Firefox's `InvalidStateError` caused by test navigation; later tests exercise Back instead and recognize visible title/footer. Both sets of raw evidence are preserved. WebGL/software-rendering and audio gesture warnings are retained in event logs; do not infer hardware performance from these runs.
