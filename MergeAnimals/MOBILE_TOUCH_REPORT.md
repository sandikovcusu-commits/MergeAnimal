# V0.8.1.2 — Mobile touch report (partial)

**Simulated mobile Chromium, not a physical Android/iOS device.** [CI 45872527367](https://github.com/sandikovcusu-commits/MergeAnimal/actions/runs/45872527367) used actual DOM touch events generated through Chromium DevTools Protocol in the Godot 4.7.2 release WebAssembly build (production code commit f16e908). Eight scripted checks passed: Play, one board touch creates exactly one drop at approximately x=260, Pause button touch does not drop, two-finger touch cancellation does not drop, fresh touch after cancellation creates one drop, resize while holding touch does not drop, Undo spends a use, and Remove plus selecting a body spends a use without a drop. `qa/browser.log`, event trace, screenshots, and saved state measurements are in the evidence ZIP. The initial failure and intermediate resize failure are preserved there as well.

Two defects were fixed: Godot 4.7.2 Web maps DOM `touchcancel` to ordinary release without setting `canceled`, so a capture-phase JavaScript marker is consumed by gameplay on that release; window resize clears held gameplay input so releasing against a changed transform cannot drop. Reference engine implementation: https://github.com/godotengine/godot/blob/4.7.2-stable/platform/web/js/libs/library_godot_input.js and https://github.com/godotengine/godot/blob/4.7.2-stable/platform/web/display_server_web.cpp.

The cancellation fix covers the gameplay aim/drop path, not a blanket proof of cancellation safety for all UI controls, Remove selection or Rescue. Multi-touch was tested only in the specific cancellation sequence, not every ordering or gesture. Touch scrolling, drag positioning, Rescue, Restart, fullscreen, tab switch and focus loss remain untested; Firefox mobile touch and real devices remain untested. Do not treat these eight checks as a complete mobile acceptance pass.
