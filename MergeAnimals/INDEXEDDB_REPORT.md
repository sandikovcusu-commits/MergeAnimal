# V0.9.0.2 — IndexedDB investigation

Godot [4.7 data paths](https://docs.godotengine.org/en/4.7/tutorials/io/data_paths.html) describes Web `user://` as virtual storage backed by IndexedDB. The [Web export documentation](https://docs.godotengine.org/en/4.7/tutorials/export/exporting_for_web.html) notes storage/cookie permission restrictions, private-browsing behavior, false positives from `OS.is_userfs_persistent()`, and background throttling.

In [Godot 4.7.2 `os_web.cpp`](https://github.com/godotengine/godot/blob/4.7.2-stable/platform/web/os_web.cpp), a persistent write close marks `idb_needs_sync`; a subsequent main-loop iteration initiates an asynchronous sync only if not already syncing. `force_fs_sync()` merely marks a request. In [Godot 4.7.2 `library_godot_os.js`](https://github.com/godotengine/godot/blob/4.7.2-stable/platform/web/js/libs/library_godot_os.js), sync errors are logged and the callback does not pass error to C++. Thus `FileAccess.close`, a timer, or that callback is not proof that a particular revision committed. Calling another independent `FS.syncfs` could race the engine's own synchronization; the new observer only reads.

Earlier Firefox immediate-close tests restored an older snapshot. The deferred snapshot and asynchronous sync offer plausible loss windows; those historical tests did not instrument the exact cause. This release does not prove that cause or eliminate it. A later readonly transaction reading matching IDBFS bytes confirms visibility of the checkpoint at that point, not durable media flush, immunity from eviction, cross-file atomicity or a future browser restart.

At code commit `58a04ee`, the unmodified production export and test probe ran in CI: Chromium run [45973023812](https://github.com/sandikovcusu-commits/MergeAnimal/actions/runs/45973023812), Firefox [45973027650](https://github.com/sandikovcusu-commits/MergeAnimal/actions/runs/45973027650). Both observed a verified checkpoint and confirmed a synthetic nonexistent entry remained pending; no page/console errors were captured in those probes. Chromium observed 28 completed write transactions, Firefox 40. Measured click-to-next-write completion is not necessarily the clicked action's own revision. Raw logs and timing JSON are in the respective CI evidence ZIPs; browser environment uses CI software rendering, not a physical device.
