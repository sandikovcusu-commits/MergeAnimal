# V0.9.1-A — “Save failed” araşdırması

## Konkret nəticə

V0.9.0.4 Web matrix-in Game Over mesajı **fixture-də etibarsız snapshot** səbəbindən yaranır; bu hadisə təkbaşına production save xətasını sübut etmir. `tests/web/QualityMatrixProbe.gd` köhnə versiyada `score = 124` və `best_at_start = 0` qoyurdu, lakin `best_score` təmiz profildə 0 qalırdı. `scripts/save/SessionSave.gd:24` etibarlı/taintsiz session üçün `best_score >= score` tələb edir. `Game.gd:1013–1019` deferred Game Over checkpoint `SessionSave.write_snapshot` çağırır; validasiya uğursuz olduqda `ERR_INVALID_DATA` (30) verir və real `Save failed` mesajı göstərilir. `Game.gd:_award_merge` normal eligible score artanda `best_score`-u, `_on_merged` isə `progression.best_score`-u yeniləyir.

## Təkrar yaratma və düzəliş

1. Instrumented Godot 4.7.2 Web build və ayrıca təmiz browser profili açılır, EN/forest fixture 12 heyvan yaradır.
2. Köhnə ssenari `score=124`, `best=0`, `best_at_start=0` ilə real `_on_game_over` çağırır. Hər iki browserdə `can_write=true`, `valid=false`, `save_status=30`, `Save failed` alındı. Eyni snapshot-ın yalnız `best_score` sahəsi düzəldildikdə `valid=true` olur: bu konkret snapshot üçün pozulan invariant təcrid edildi.
3. Fixture-də score ilə birlikdə `best_score` və `progression.best_score` yeniləndi; `best_at_start=0` yeni rekord görüntüsü üçün saxlandı. Production validator, Game Over save və status mesajı dəyişdirilməyib və gizlədilməyib.
4. Yeni ayrıca profildə eyni fixture `score=best=124`, valid snapshot, `save_status=0`, boş xəta mesajı, `game_over_pending=true` və eyni session ID ilə checkpoint verir. Tracked IDBFS entry-lərinin exact byte read-back `verified` oldu; refresh-dən sonra session ID, score, pending state və generation qorundu.

## Yeni P1: uzunömürlü pending merge / save dayanması

Passiv probe ilə təkrar [Firefox 46071244975](https://github.com/sandikovcusu-commits/MergeAnimal/actions/runs/46071244975) və [Chromium 46071248324](https://github.com/sandikovcusu-commits/MergeAnimal/actions/runs/46071248324) də təbii Game Over hədəfinə çata bilmədi (**FAILED**). Hər iki halda game PLAYING/unpaused, `achievement_blocked=false`, oyun vaxtı artdığı halda eyni pending merge cütləri sabit qaldı; `_session_snapshot` boş idi və 115–120 input aralığında spawn artmadı. Firefox-da iki cüt (rabbit→cat və cat→dog), Chromium-da hamster→rabbit müşahidə edildi. `Game.gd:_attempt_drop` pending olduqda drop-u rədd edir, `save_session` `ERR_BUSY` qaytarır; `_session_snapshot` locked body olduqda boş qalır. `MergeManager.gd:_commit_pending` təhlükəsiz nəticə yeri tapmadıqda pending saxlayıb təkrar edir. Səbəb bu liveness yolundadır; konkret niyə həmin cütlər üçün yerləşmə tapılmadığının ayrıca minimal təkrar testi hələ lazımdır.

Əvvəlki passiv Firefox [46070283328](https://github.com/sandikovcusu-commits/MergeAnimal/actions/runs/46070283328) run-da canlı xal **587**, son oxunan checkpoint **427**, observer **verified** idi; `verified` yalnız son yazılmış byte-lara aiddir və yazılmamış hazırkı oyunu təsdiqləmir. Heç bir real refresh zamanı itki bu konkret run-da ölçülməyib, amma pending vəziyyət davam etdikdə məlumat itkisi riski var. Bu P1 açıqdır və düzəldilməyib. Fizikanı və merge mövqeyini təsadüfi dəyişmək riskli olduğu üçün, təhlükəsiz düzəliş üçün əvvəl yer/overlap və xal invariantları ilə minimal reproduksiya, əvvəl/sonra test, browser və 100-seed regressiyası tələb olunur. Raw trace log-ları `docs/qa/v091-a/trace-*.log` və `observe-*.log`.
